description: 引数で指定したPRで行なった依存ライブラリのバージョンアップに従うレビューを行います
argument-hint: <PR番号>
arguments: pr_number
allowed-tools: Bash(git:*), Bash(gh:*), Bash(npm:*), Bash(cat:*), Read, WebSearch, WebFetch, Grep
---

PR番号 = $pr_number

※ PR番号（$pr_number）が渡されていない場合はエラーメッセージを表示して終了してください。

## 手順

### 1. PR情報の取得

`gh pr view {PR番号}` および `gh pr diff {PR番号}` を使用して、PRの概要と変更差分を取得してください。

### 2. 依存ライブラリの変更検出

差分から依存ライブラリの変更を検出してください。対象ファイルの例：

- `build.sbt`, `project/plugins.sbt`, `project/*.scala` (Scala/sbt)
- `package.json`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml` (Node.js)
- `requirements.txt`, `pyproject.toml`, `poetry.lock`, `Pipfile.lock` (Python)
- `Gemfile`, `Gemfile.lock` (Ruby)
- `go.mod`, `go.sum` (Go)
- `Cargo.toml`, `Cargo.lock` (Rust)
- `*.tf` (Terraform providers)
- `flake.nix`, `flake.lock` (Nix)

変更前後のバージョンを一覧化してください。

### 3. 各ライブラリの変更内容調査

変更されたライブラリそれぞれについて、以下を調査してください：

- 公式のChangelog/Release Notesを確認（GitHub Releasesページ等）
- 変更前バージョンから変更後バージョンまでの間に含まれる変更を確認

### 4. レビュー観点

以下の観点でレビューを行ってください：

- **Breaking Changes（破壊的変更）**: API変更、削除されたメソッド/クラス、シグネチャ変更
- **非推奨API（Deprecation）**: 今回のバージョンで非推奨になったAPIをプロジェクト内で使用していないか
- **マイグレーション対応漏れ**: 公式マイグレーションガイドの手順がすべて実施されているか
- **推移的依存関係の影響**: transitive dependencyの変更による間接的な影響
- **セキュリティ**: CVE/セキュリティアドバイザリの有無、脆弱性修正の確認
- **動作互換性**: ランタイムバージョン要件の変更（Java/Node.js/Python等の最低バージョン）

### 5. プロジェクト内の影響範囲確認

変更されたライブラリのAPIを使用している箇所をプロジェクト内で検索し、影響を受けるファイルを特定してください。

### 6. 結果出力

レビュー結果はマークダウンファイルに書き出してまとめてください。以下の構成で記載してください：

```
# 依存ライブラリ バージョンアップレビュー
## PR情報
## 変更されたライブラリ一覧（変更前 → 変更後）
## 各ライブラリの詳細レビュー
### ライブラリ名
- Breaking Changes
- Deprecations
- マイグレーション対応状況
- セキュリティ
## プロジェクト内の影響範囲
## 総合評価・指摘事項
```

レビューとマークダウンファイルの確認は3回繰り返して行い精度を高めるようにしてください。

### 7. PRへのレビューコメント投稿

手順6のレビュー結果をもとに、PRにレビューコメントを投稿します。

#### 7-1. コメント内容の作成

以下のテンプレートに沿ってコメントを作成してください。

**対応不要の場合:**

```markdown
## 📦 依存ライブラリ バージョンアップレビュー

### 更新内容
| パッケージ | 変更 | 種別 |
|---|---|---|
| package-name | 1.0.0 → 2.0.0 | major/minor/patch |

### 主な変更点
- [箇条書きで要約]

### 本プロジェクトへの影響
- **Breaking Changes**: なし / あり（ただし利用箇所なし）
- **Deprecations**: なし / あり（詳細を記載）
- **セキュリティ**: 問題なし / CVE修正あり（詳細を記載）
- **修正が必要か**: いいえ

---
🤖 Generated by Claude Code
```

**対応必要の場合:**

```markdown
## 📦 依存ライブラリ バージョンアップレビュー

### 更新内容
| パッケージ | 変更 | 種別 |
|---|---|---|
| package-name | 1.0.0 → 2.0.0 | major/minor/patch |

### 主な変更点
- [箇条書きで要約]

### ⚠️ 対応が必要な項目

#### Breaking Changes
- [影響箇所とその内容]

#### 非推奨API
- [該当箇所とその内容]

#### マイグレーション対応漏れ
- [未対応の手順]

#### セキュリティ
- [CVE情報と影響]

### 影響を受けるファイル
- `path/to/file1.ext` (L行番号): [影響内容]
- `path/to/file2.ext` (L行番号): [影響内容]

### 対応の方向性
- [推奨される修正方針]
- Migration Guide: [URLがあれば記載]

---
🤖 Generated by Claude Code
```

※ 該当しないセクションは省略してください。

#### 7-2. ユーザーに確認

作成したコメント内容の全文をターミナルに表示し、投稿の許可を得てください。

#### 7-3. コメントを投稿

ユーザーの承認後、以下のコマンドで投稿してください：

```bash
gh pr comment {PR番号} --body "レビュー内容"
```
